> 一个做了几十个 App 的开发者，和一个给编码代理装地板的 Skill，回答的是同一个问题。

这段内容来自一份视频文案。作者把自己这两年用 AI 做的东西摆出来，记账、阅读、字幕、股票复盘、资产管理，一个都不算精致，但都没有 AI 味。他说这件事没有一句话的捷径，只能花精力调教。我看的时候一直在对照上一篇写 Hallmark 的笔记，一个讲怎么做得好，一个讲怎么不出丑，摆在一起反而都更清楚了。

## 一、AI 味的本质是泛滥，不是难看

他先做了一次拆解：把那个蓝紫渐变的页面单独拿出来看，颜色没错，字体没错，间距和按钮都没问题。所有零件单看都合格，合起来一眼就能认出是 AI 做的。

他的解释是椰子鞋。刚出来时少数人穿，看着酷；国产替代铺满街之后，同样的鞋变得普通，甚至有点土。AI 生成的界面同理，人人都能生成，满大街都是，审美疲劳随之而来。

Hallmark 那边给的是另一套描述。它把这类页面的固定痕迹一条条列出来：标题上方一行全大写的灰色小标签，标题里有个词染成紫色，三张圆角卡片配 emoji，一条紫蓝渐变，底部挂个订阅框。

两种说法不冲突，合起来才是完整定义：AI 味 = 可枚举的视觉词汇 × 大规模重复。光是重复，没有固定的那一套套路，构不成识别特征。套路摆在那里没人用，也谈不上 slop。前者解释为什么看腻，后者说明腻的到底是什么。

这个乘法关系能拿来用。想降低 AI 味，要么削减重复，要么削减词汇。后者更容易动手，因为词汇本身可以枚举，可以列成清单。

他还特意排除了一类情况：元素重叠、配色明显出错，那不叫 AI 味，那叫没做完。这个界限得先划清，否则讨论会跑偏成审美优越感。

## 二、蓝紫渐变的来历

视频里提到一段公案：Tailwind CSS 的作者在社交媒体上为那个蓝紫色道歉。他在 Tailwind UI 里设了 `bg-indigo-500`，五年前的事。Tailwind 用量大，AI 训练数据里自然吃进大量这个颜色，于是生成器都往 indigo 上靠。

五年前用这个配色没有问题，当时的作品里到处都是，它属于那个时代的正常选择。

到了 2026 年，AI 更爱出米黄、紫黄一类的页面。文案的判断是 Claude 带起了一波设计风潮，大家开始用这套配色，AI 又把它学了进去。

所以 slop 会换衣服。2022 年是蓝紫，2026 年是米黄，下一个还不知道。作者引了一句老话，唯一不变的是变化。

这句话对认知有帮助，对产出没帮助。Hallmark 选择在流程里动手：`theme.mjs deal` 每次发三张主题牌，脚本记日志，比对最近三次用过的组合，尽量避开。它不指望模型自觉，直接把形状、首屏姿态、导航、页脚从模型手里拿走。

这两件事可以并存。认知上接受均值永远存在，省下跟它较劲的力气；流程上把随机性交给脚本，避免连续十页塌到同一个审美重心。先接受它，再绕开它。

## 三、先定出发点

他把做界面的目的分三类。

为了艺术，纯粹做好看的东西，让人记住你。

为了工业，用最低成本最快速度解决问题，长什么样不重要。工业设备的操作界面、后台管理系统都是这一类。

为了商业，吸引消费、提供情绪价值，在设计和商业之间找平衡。

艺术和商业是天平两端，工业偏在完成任务那一侧。

这个分类不是玄学，它直接决定要不要上重工具。后台管理系统用 Ant Design 拼出来就够，不必过 Hallmark 那 88 条闸门；面向用户的落地页或作品页，才值得为辨识度付出成本。Hallmark 自己也承认，随便糊个页面的话这套流程是负担，`--fast` 能走快车道，地板和静态检查照样生效。

## 四、找对标，攒自己的库

他推荐四个地方去找。

Dribbble，设计师作品集，以 web 和 app 的静态图为主。

Awwwards，收集网站并定期颁奖，风格偏艺术，能点进原站看真实交互。

Mobbin，真实商业产品为主，web 和 app 都有，做商业参考更合适，收费。

GitHub，别人已经开源做过的，直接改或参考实现。

比清单更有用的是他后面那句话：看到好的 UI 就存下来，建一个自己的灵感库，没事翻一翻。翻的过程会生出新想法，也会发现自己以前哪里做得不对。

Hallmark 把这件事做成了机器版本：50 个主题，每个不超过 8 KB，规定纸张、字体、颜色配额、表面和组件语言，配一张成品截图。它明确说主题是材料不是模板，不规定页面包含什么、顺序如何，同一个主题配两个 prompt 会出两个页面。

两条路的同质化风险一样存在。人肉灵感库用久了，你会反复回到自己偏爱的几种风格；50 个主题用的人多了，`cobalt` 配 `dusk` 也会变成新的一眼 AI。Hallmark 留给这种情况的出口是 `custom`，主题和版式文件全部作废，只剩地板、闸门和一份 `direction.md`。

## 五、组件库给共性，token 出个性

他列的组件库清单分两端。

B 端提到 Ant Design、Element UI、Arco Design、TDesign。这里有一处需要修正：文案说四家都有 React 和 Vue 版本，实际 Ant Design 以 React 为主，Element 以 Vue 为主，Arco 和 TDesign 两边都覆盖。TDesign 是腾讯出品，支持小程序，做小程序可以优先考虑。

C 端是 HeroUI、MUI、shadcn/ui。MUI 对应 Google 的 Material Design；shadcn/ui 把组件源码直接放进项目，改源码就等于改组件，底层仍依赖 Radix 和 Tailwind，所以它不是零依赖，只是把可定制的部分交给了你。作者个人最常用 HeroUI，理由是它比 shadcn/ui 更细致。

这里有个矛盾。组件库保证一致性和速度，同时是千人一面的直接来源。Ant Design 风格的表格、左色条卡片、圆角阴影，用的人越多越像。

Hallmark 的反套路清单几乎正好覆盖这些默认视觉：卡中卡、emoji 当图标、卡片左侧一条有色 border、字距拉开的小型大写标签。视频里也提到，左色条 border 在几年前是后台指标卡片的经典做法，放在五年前没问题，放到现在人人都有就是问题。

三样东西因此各管一段：组件库决定结构正确和交付速度，design token 决定表面辨识度，闸门清单决定下限。它们不在同一个层面上竞争。

## 六、三层设计系统

最后他落到三层结构，这是整段内容里最可复用的部分。

第一层是 `design.md`。产品基本信息、视觉相关的字体颜色间距 shadow、组件怎么用，特殊组件有特殊交互也写进去。这个概念最早由 Google Stitch 提出，早期这些内容放在 `CLAUDE.md` 里，后来拆出来；模型能力上来之后，`CLAUDE.md` 不必写太多东西，但设计约束仍值得单独成文。

第二层是 UI 组件库，负责快速搭出能用界面，代价是长得像别人。

第三层是 design token。前端和设计师对这个词不陌生，落到代码里就是 CSS 变量。改颜色、字体、边距这些数字，联动一组样式，整体换掉组件外观，同时不损失组件能力。这一步才真正做出自己的风格。

如果项目里还没有 `design.md`，可以让代理读一遍现有代码总结一份。总结出来的那份就是你自己的风格，不是别人的。

Hallmark 在这三层上有个很干净的接口。它的第一步 pre-flight 要求先读项目，`design.md` 优先级最高，其次是品牌规范、现有字体调色板；地板条款要求颜色字体全走 `:root` token。视频讲的「为什么该写 design.md」和「为什么要用 token」，到 Hallmark 这里变成两条必须通过的检查项。一个给理由，一个给审法。

还有一条我觉得挺聪明：同一条豁免连续三次，判定为项目自有风格，这时该写一份 `design.md` 固化。我见过的设计规范大多是先定规矩再执行，这条反着来，先长出来，再固化成文。

## 七、两套方法摆在一起

| 维度 | 视频方法 | Hallmark |
| --- | --- | --- |
| 方向 | 正向建模，做得好 | 负向约束，不出丑 |
| 主要手段 | 对标、灵感库、组件库、design token | 16 条地板、88 条闸门、sloplint |
| 作用范围 | 从定位到设计系统的全链路 | 单页落地页的构建过程 |
| 对 AI slop 的态度 | 承认它永远存在，跟着变 | 用发牌和 custom 模式主动去相关 |
| 主要成本 | 前期找素材、攒库的时间 | 每次构建读六七份参考，两轮渲染评审 |
| 失效场景 | 见过很多但收不拢，做不出判断 | 只会排除不会创造，上限仍看模型 |

补位关系很清楚。视频方法解决想不到，Hallmark 解决手会滑。前者需要审美判断，后者只需要遵守清单。

我实际的用法是两套都上：新项目先写 `design.md` 和 token，组件用 HeroUI 或 shadcn/ui 起骨架，交付前拿 `gates.md` 当自查表扫一遍。顺序不能反，先有设计意图，再谈禁令，否则清单只会把页面改成一个干净的空白。

## 八、一句话生成这件事

视频作者开头就说了，一句话生成好看界面的说法不可信，做有质感的 App 仍要花大量精力调教。他也承认 web design 平台有用，但用途是出原型：v0 用来试 prompt 和市场模板，Lovable 能连后端还能部署，Stitch 提出了 `design.md` 这个概念，Claude Design 目前是原型输出最强的一个，还在 beta。

我同意前半句，对后半句保留意见。原型平台的价值在于把想法变成能点的东西，但原型上线率一高，这些平台自己的默认风格就会成为下一批 slop。Stitch 提出 `design.md` 这件事比它的生成能力更重要，因为它给了人一个可携带的资产：平台可以换，文档跟着项目走。

## 九、小结

AI 味来自均值，均值来自训练数据里最高频的那批选择。它会一直存在，也会一直换款式。能做的事就那几件：写清楚自己的想法，找真实的对标，用 token 把组件改成自己的样子，再用一份清单兜住下限。

在上一篇 Hallmark 的笔记里我写过，它最有价值的不是 50 个主题，是 `gates.md`。看完这段视频，这个判断没变，但补了一半：清单管下限，`design.md` 管上限。
